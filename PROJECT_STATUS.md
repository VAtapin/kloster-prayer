## Реализовано и принятые решения
- Stripe: раскрываемая пошаговая помощь в настройках EN/RU/DE/UK/PL, официальные Dashboard API keys/Webhooks ссылки, Sandbox/Live, Snapshot/Your account, точный webhook URL, события разовых/регулярных платежей, whsec_, тестовая оплата и диагностика доставок. Документация Stripe сверена 11.10.2026.
- Исправлен порядок admin_menu: родитель регистрируется на priority 9 перед feature submenu. Сборы и регулярная поддержка получают правильные page hooks и admin.php?page=…; причина прежних 404 воспроизведена регрессионным тестом.
- Админка Kloster → Помощь → Шорткоды: все 9 шорткодов, точные параметры/значения по умолчанию и 15 примеров с копированием. Переключение EN/RU/DE/UK/PL меняет справку и lang в примерах; при запрете буфера обмена пример выделяется для ручного копирования. Доступ по manage_options, адаптивное отображение.
- Подача записок и пожертвования вместе с записками сохранены. Самостоятельная форма [kloster_donation lang="ru"]: EUR 0,50–999 999,99; пожертвования не создают требы или молитвенные PDF.
- Целевые сборы: названия/описания EN/RU/DE/UK/PL, цель, срок и draft/open/closed. Сотрудник с manage_options создаёт сборы и вводит расходы отдельно. Сервер запрещает новые оплаты и подписки закрытых/просроченных сборов.
- [kloster_campaigns], [kloster_campaigns id="1"], [kloster_campaign_report id="1"]: публичные агрегированные поступления, расходы и остаток без данных жертвователей. Подтверждённые частичные возвраты уменьшают поступления, полные исключают платёж.
- [kloster_donation_history lang="ru"]: только текущий WordPress user_id, пагинация, статусы/возвраты и собственные соглашения поддержки. Гостевые/старые платежи не привязываются по email. Приватные страницы отключают штатный page cache; внешний кеш нужно исключить отдельно.
- [kloster_support lang="ru" campaign_id="1"]: вошедший пользователь выбирает месяц/год и явно соглашается на повторные платежи. Stripe Checkout subscription и PayPal subscriptions API используют существующие credentials. Тариф PayPal для новой суммы/периода готовится через WP-Cron; затем пользователь повторяет отправку.
- Только подписанные события подтверждённого списания создают поступление; активация/return URL этого не делают. Каждое списание отдельно; provider/payment key и refund ledger исключают дубли. Поддержаны новые/старые формы Stripe invoice, задержанные события и PayPal lifecycle; отменённое соглашение не возобновляется поздним событием.
- Владелец отменяет поддержку в истории, сотрудники — в Regular support; проверяются nonce/ownership/capability. Отмена фиксируется после подтверждения API. Закрытие сбора не прекращает уже согласованную поддержку; отмена не возвращает прежние платежи.
- Схема 1.2.15 совместимо добавляет campaigns/expenses/subscriptions/payment_refunds и необязательные поля заказов. Записки и прежние состояния полного возврата сохранены; неизвестные исторические суммы возвратов не реконструируются.
- 359 английских gettext msgid; полные PO/MO ru_RU/de_DE/uk/pl. Прежние переводы форм и пожертвований сохранены. Пользовательские имена/комментарии/названия не переводятся автоматически.
- Прежние Stripe/PayPal, оригинальные PDF-бланки, архив, комментарии, CSV и уведомления сохранены. Email получателя задан отдельно; пустое поле отключает уведомления, admin_email не подставляется; повторы через WP-Cron.
- GPLv2-or-later оригинальных бланков подтверждена владельцем; лицензии библиотек/шрифтов/иллюстраций включены в ZIP. Frontend build не требуется.
