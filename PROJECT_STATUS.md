# Состояние проекта

## Текущее состояние
- WordPress-плагин kloster-prayer, версия 1.2.5, PHP 8.4. Репозиторий https://github.com/VAtapin/kloster-prayer.git, main → origin/main.
- Имя, шорткоды и REST-адреса webhook сохранены. Переименование отменено владельцем.
- Установка через ZIP в WordPress; production не менялся, настоящие письма не отправлялись.

## Реализовано
- Stripe/PayPal, формы, отчёты, оригинальные PDF-бланки, архив и история записок.
- PDF автоматически отмечает печать; дата заказа выводится только на сорокоусте.
- Видимый архив и нормализация имён через запятую в форме, сохранении и PDF.
- Настраиваемый HTTPS-домен API: пустое значение следует за WordPress; путь webhook прежний.
- 1.2.5: отдельный email получателя оплаченных записок в настройках. Пустое поле отключает уведомления; admin_email не используется.
- Таблица klp_notifications добавляется через dbDelta без удаления прежних данных. В очередь попадают только новые переходы к paid при включённой настройке; старые оплаченные заказы не рассылаются.
- Независимое HTML-письмо содержит требы, тип, имена, примечание, жертвователя, сумму и защищённую ссылку в WordPress. Письмо жертвователю не изменено.
- Уникальная очередь по заказу, блокировка параллельных работников с восстановлением через 15 минут; ошибки повторяются существующим почасовым WP-Cron. Смена email применяется к ожидающим письмам; пустой адрес приостанавливает их. События записываются в историю.

## Ограничения и следующие шаги
- Перед установкой сохранить резервную копию БД. Установить ZIP 1.2.5, указать email в «Настройки → Уведомления о записках» и проверить доставку на тестовой оплате.
- Интеграционная проверка dbDelta на настоящей WordPress/MySQL и реальная SMTP-доставка не выполнялись.
- Успех wp_mail означает передачу почтовой системе, не доставку в Inbox. При аварии между отправкой и сохранением результата возможен повтор письма.
- Требования WordPress.org по внешним сервисам и полный аудит готовности к каталогу остаются отдельной незавершённой задачей.
- Страница скачивания Kalendar пока содержит 1.2.4; установка текущего ZIP выполняется отдельно. Git push не означает обновление рабочего сайта.
