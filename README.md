# Пожертвования

WordPress-плагин для приходов, храмов, соборов и монастырей: молитвенные записки, требы, пожертвования, платежи Stripe и PayPal, PDF-бланки и отчёты.

## Установка

Для ручной установки и проверки используйте `output/georg-kloster-orthodox-donations-1.0.6.zip`: **Плагины → Добавить новый → Загрузить плагин**. Это независимый плагин: отдельные PHP-классы, шорткоды `gkod_*`, стили, скрипты, таблицы, настройки и webhook-адреса. Прежний плагин может оставаться включённым; его записки, платежи и переводы не импортируются и не изменяются. Настройте оплату нового плагина и зарегистрируйте его webhook-адреса в Stripe/PayPal. На страницах нового плагина используйте новые шорткоды из раздела помощи.

После активации откройте **Пожертвования → Настройки** и внесите данные Stripe и/или PayPal. Создайте webhook-адреса, показанные на этой странице настроек. Плагин не содержит и не публикует платёжные ключи.

В панелях Stripe и PayPal раскрывается пошаговая помощь. Stripe содержит прямые
ссылки на API keys и Webhooks/Workbench, выбор Snapshot-событий, получение секрета
подписи, проверку тестовых оплат и разбор ошибок доставки webhook.

Чтобы синхронизировать каталог Stripe, сначала сохраните ключ Stripe нужной среды,
затем откройте **Пожертвования → Требы**, отметьте нужные строки и выберите в меню
**Действия** пункт **Синхронизировать выбранные со Stripe**. Для каждой отмеченной
требы создаётся или обновляется продукт, основная цена в EUR и доступное изображение;
основное название и описание берутся из немецких полей требы. При оплате
Checkout использует Stripe Price ID и количество из расчёта требы: например, пять
имён при цене €30 за имя передаются как одна позиция с количеством 5. Для цены за лист
передаётся рассчитанное число листов. Имена людей и комментарий в Stripe не отправляются.
Тестовые и боевые ключи получают отдельные связи с товарами. После изменения названия,
описания, картинки или цены снова выполните синхронизацию; до неё оплаты продолжают
работать прежней единой строкой с общей суммой.

Требования: WordPress 7.1+, PHP 8.4+, HTTPS для Stripe и PayPal.

Подготовка к WordPress.org, сведения о проверках и ограничения: [docs/WORDPRESS-REVIEW.md](docs/WORDPRESS-REVIEW.md).
Исправления предварительной проверки, escaping/nonce/права и подробный аудит: [docs/SECURITY-REVIEW-1.0.5.md](docs/SECURITY-REVIEW-1.0.5.md).
Каноническое имя для каталога — Georg Kloster – Orthodox Donations; слаг остаётся georg-kloster-orthodox-donations.
Нельзя считать Git push публикацией в WordPress.org или обновлением сайта.

С версии 1.2.5 в настройках есть отдельный **Email получателя** уведомлений об оплаченных записках.
Адрес администратора не используется. Пустое поле отключает уведомления; старые заказы автоматически
не рассылаются. Подтверждение жертвователю сохраняется. Ошибки передачи повторяются через WP-Cron;
успешная передача письма почтовой системе не гарантирует попадания во «Входящие».

Для самостоятельных разовых пожертвований добавьте на отдельную страницу
`[gkod_donation lang="ru"]`. Имена и выбор требы не нужны; оплата и подтверждение
используют существующие настройки Stripe/PayPal.

Целевые сборы создаются в **Пожертвования → Campaigns**. Публичный список:
`[gkod_campaigns lang="ru"]`, отдельный сбор: `[gkod_campaigns id="1" lang="ru"]`,
отчёт: `[gkod_campaign_report id="1" lang="ru"]`. Оплаты учитываются только после
подтверждения; расходы сотрудник с правом `manage_options` вводит отдельно.
Черновики не публикуются, закрытые и просроченные сборы не принимают новые оплаты.

`[gkod_donation_history]` показывает вошедшему пользователю только платежи,
сделанные из его учётной записи. Гостевые и старые платежи автоматически по email
не привязываются. Публичные отчёты не показывают имена или контакты жертвователей.

Регулярная поддержка: `[gkod_support lang="ru"]` или
`[gkod_support lang="ru" campaign_id="1"]`. Вошедший пользователь выбирает сумму
и период (месяц/год), явно соглашается на повторные списания и подтверждает их на
странице Stripe/PayPal. Каждый подтверждённый платёж появляется в личной истории;
там же можно отменить поддержку. Для сотрудников доступен раздел Regular support.
Закрытие сбора запрещает новые подключения, но не отменяет уже согласованную поддержку.

Для подписок добавьте события webhook из настроек плагина: Stripe —
`invoice.payment_succeeded`, `invoice.payment_failed`, `customer.subscription.created`,
`customer.subscription.updated`, `customer.subscription.deleted`, `charge.refunded`;
PayPal — `PAYMENT.SALE.COMPLETED`, `PAYMENT.SALE.REFUNDED`, `BILLING.SUBSCRIPTION.CREATED`,
`BILLING.SUBSCRIPTION.ACTIVATED`, `BILLING.SUBSCRIPTION.CANCELLED`,
`BILLING.SUBSCRIPTION.EXPIRED`, `BILLING.SUBSCRIPTION.SUSPENDED`,
`BILLING.SUBSCRIPTION.PAYMENT.FAILED`. Существующие события разовых оплат сохраните.
Один возврат на сайт или активация подписки не подтверждают поступление денег.

Нужен работающий WP-Cron: PayPal готовит тариф для новой суммы/периода в фоне;
при сообщении о подготовке повторите отправку через некоторое время. Подтверждённые
частичные возвраты уменьшают поступления, полные исключают платёж из поступлений.
Прежние записи полного возврата сохраняются; неизвестные исторические суммы не восстанавливаются.
Страницы личной истории и поддержки исключите из внешнего полного кеша/CDN.
Обновление схемы выполняется автоматически и сохраняет прежние записки.

## Возможности

В админке **Пожертвования → Помощь → Шорткоды** доступны все шорткоды, их параметры и
примеры с кнопками копирования. Справка следует языку админки WordPress;
редакторы форм, треб и сборов показывают только текущий язык WPML/Polylang.
Сохранённые переводы других языков остаются без изменений. Примеры шорткодов
по умолчанию не фиксируют язык; на сайте используется текущий язык языкового плагина.

- формы треб и пожертвований, включая совместимые шорткоды;
- русский, немецкий, украинский и польский переводы;
- Stripe Checkout и PayPal Checkout с проверкой webhook-подписей;
- PDF-бланки здравия и упокоения, CSV-экспорт, печать и отчёты;
- архивирование вместо удаления, журнал событий и повторная отправка подтверждений.

Полная документация по шорткодам, установке и изменениям версий содержится в [readme.txt](georg-kloster-orthodox-donations/readme.txt).

Исходные строки интерфейса на US English, четыре перевода находятся
в стандартных POT/PO/MO-каталогах WordPress. Сохранённые имена, комментарии,
названия треб и содержимое форм не переводятся и не перезаписываются автоматически.

## Выпуск

Номер версии должен совпадать в `georg-kloster-orthodox-donations/georg-kloster-orthodox-donations.php` и `georg-kloster-orthodox-donations/readme.txt`. Теги имеют вид `georg-kloster-orthodox-donations-<версия>`. После разрешения владельца тег запускает `.github/workflows/release.yml`: проверки PHP/PDF/платежей/переводов, сборку и GitHub Release, затем публикацию в WordPress.org. До успешного завершения release job SVN не меняется.

- `georg-kloster-orthodox-donations-<версия>.zip` — архив конкретного выпуска;
- `georg-kloster-orthodox-donations-wordpress-org-<версия>.zip` — пакет для заявки в каталог;
- `georg-kloster-orthodox-donations.zip` — постоянное имя для скачивания последней версии.
- `georg-kloster-orthodox-donations-wordpressorg-assets.zip` — отдельные материалы страницы каталога.

Job `deploy-wordpress-org` использует проверенный каталоговый пакет без PO/MO и публикует его в SVN `trunk` и `tags/<версия>`, а `wordpressorg-assets` — в SVN `assets`. Slug закреплён в workflow. `SVN_USERNAME` и `SVN_PASSWORD` хранятся в GitHub Actions secrets; используются только на шаге публикации. Параллельные публикации запрещены. Ошибочный job можно повторить в Actions; существующие SVN tags не переписываются.

После успешных проверок и commit/push выпуск 1.0.5 запускается так:

```text
git tag georg-kloster-orthodox-donations-1.0.5
git push origin refs/tags/georg-kloster-orthodox-donations-1.0.5
```

Это публикация плагина в каталоге, а не установка на сайты владельца. Не создавайте повторный тег, если он уже существует. Проверяйте результат обоих jobs и публичный пакет WordPress.org.

## Пакет для WordPress.org

Для заявки используйте `output/georg-kloster-orthodox-donations-wordpress-org-1.0.5.zip`. По опыту успешной публикации wp_cu_translator этот пакет содержит POT и исходники, но исключает PO/MO. Четыре перевода остаются в репозитории и обычном установочном ZIP; версия каталога загружает стандартные WordPress language packs из `wp-content/languages/plugins`. До публикации переводов на translate.wordpress.org каталоговая версия показывает английский интерфейс. Сохранённый язык писем и PDF также поддерживает language packs.

Воспроизводимая сборка обоих пакетов из корня проекта:

```text
python tools/build-package.py
```

Проверки перед выпуском описаны в [docs/WORDPRESS-REVIEW.md](docs/WORDPRESS-REVIEW.md). Запрос одобрен WordPress.org 16.10.2026. Публикацию запускает разрешённый владельцем Git-тег; сайты владельца автоматически не обновляются.

Иконки, русские баннеры и шесть настоящих скриншотов подготовлены отдельно в `wordpressorg-assets/`; архив — `output/georg-kloster-orthodox-donations-wordpressorg-assets.zip`. Они загружаются в SVN `assets` после одобрения заявки. Подписи в readme английские. Состав и получение: [docs/WORDPRESS-ORG-ASSETS.md](docs/WORDPRESS-ORG-ASSETS.md).
